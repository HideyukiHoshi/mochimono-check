# もちものチェック PWA — iPhone 8 / iOS 16.7.16 対応

## このアプリでできること
- 持ち物の登録・名前変更・削除（初期例：筆箱、連絡帳、水筒、宿題ノート、上履き）
- 各持ち物に固有のQRコードを生成、PNG画像保存、印刷/PDF保存
- iPhoneの背面カメラでQRを連続読み取り、その日の確認済みに変更
- リスト上から手動でもチェック可能（QRが汚れた場合など）
- 日付が変わると「きょうのチェック」は未確認になる。QRは再発行不要
- JSONバックアップの書き出し・復元（同じQRシールを引き続き使用可能）
- チェック状態や登録情報は端末のブラウザ内に保存。アカウント・バックエンド不要
- 初回キャッシュ完了後はオフライン起動・スキャン可能

## 重要：iPhoneで試すにはHTTPSが必要
iPhoneの「ファイル」アプリから index.html を直接開く方式では、カメラアクセスおよびService Workerが動作しません。
Web上にHTTPSで置いてSafariから開いてください。**GitHub Pages（公開リポジトリ）なら無料**でホストできます。

### GitHub Pagesへの設置（簡単な手順）
1. GitHubにログイン（なければ無料アカウントを作成）。
2. `mochimono-check` などの **Public** リポジトリを新規作成。
3. このZIPをiPhoneの「ファイル」アプリで解凍して、できたフォルダの中の**ファイル11個をすべて選択**し、GitHubリポジトリのルートへアップロード。ZIPファイル自体をアップロードしないこと。
4. リポジトリの `Settings` → `Pages` で `Deploy from a branch` を選択し、`main` ブランチの `/(root)` を指定して `Save`。
5. GitHub Pagesで発行されるHTTPS URL（例：`https://USERNAME.github.io/mochimono-check/`）をiPhone 8の **Safari** で開く。
6. **最初はオンラインで開く**。画面右上が **「オフライン準備OK」** になるのを確認。
7. Safariの共有アイコン → **「ホーム画面に追加」** →「追加」。ホーム画面のアイコンから起動。
8. **ホーム画面版でも最初の起動はオンラインで行い**、「オフライン準備OK」を確認。その後は機内モードで起動・確認を試す。

補足：GitHub PagesではHTML/JSソースが公開されますが、持ち物の登録情報はiPhoneのローカルストレージに置かれ、GitHubにアップロードされません。QR内にはランダムIDだけを記録します。

### 最初のセットアップ
1. ホーム画面版アプリの「もちもの」を開き、不要な初期例を削除し、実際の持ち物を追加。
2. 各持ち物の「QR」から画像を保存・印刷するか「QRシールを印刷 / PDF保存」を使う。
3. 各QRを切り分けて持ち物に貼る。ラミネートや透明テープで保護する場合は反射に注意。
4. 「きょう」→「QRコードをスキャン」→カメラを許可して、貼ったQRを1つずつ読み取る。
5. 緑色の「確認できたよ！」を見て、次の持ち物にカメラを向ける。

### 持ち物データの注意点
- データ保存先はこの端末の `localStorage` です。iCloudやサーバーとの同期はありません。
- iPhoneのホーム画面版とSafariの通常タブは、別の保存領域になる場合があります。**登録・バックアップ復元はホーム画面版で**行ってください。
- SafariのWebサイトデータ削除、iOSのストレージ管理、アプリ削除や端末故障でデータが失われる可能性があります。**「もちもの」→「バックアップを書き出す」を定期的に実行**してください。
- バックアップには持ち物の名前と識別子が含まれます。ファイルを他人に公開しないでください。
- 既存QRのラベルに貼られたIDは、リストを削除して新規登録すると変わります。バックアップから復元すると以前のQRを再利用できます。
- 初回の jsQR ライブラリの取得にはインターネットが必要です。読み込みまたはキャッシュに失敗した場合は、オンラインでSafariから開き直してください。
- iOS 16のカメラ権限ダイアログは、Webアプリの起動時などに再表示される場合があります。

### PCでの画面確認（開発用）
このフォルダでターミナルから `python -m http.server 8000` を実行し、PCブラウザで `http://localhost:8000` を開きます。localhostは安全なコンテキストとして扱われます。
iPhoneからPCの `http://192.168...:8000` にアクセスする方法はHTTPSではないため、カメラは原則使用できません。


## 技術情報
- iOS 16 / Safariの `navigator.mediaDevices.getUserMedia` と `<video playsinline>` でカメラを扱います。
- QR解析には[jsQR v1.4.0](https://github.com/cozmo/jsQR)（Apache 2.0）を採用。初回オンライン読み込み後、Service Workerが外部スクリプトをキャッシュします。
- QR作成は同梱のQRコード生成スクリプト（MIT）。
- QR内容は `MCHK:UUID` のみ。氏名や学校名は含まれません。
- 処理は端末内のみで、スキャン画像やリストはサーバーへ送信しません。
- Service WorkerやHTMLを更新した際には、sw.jsのCACHE_NAMEを更新すると、キャッシュの入れ替えが行われます。

## 動作確認の範囲
PC上のChromiumでリストの操作・QR画像生成・印刷用レイアウトを検査する構成です。**実機iPhone 8 / iOS 16.7.16 のカメラによる読取は、端末なしでは検証できていません。** まず実機で複数ラベルを連続スキャンして確認してください。

## iPhone だけで GitHub Pages に設置する手順
1. ChatGPTのZIPリンクをSafariでダウンロードし、「ファイル」アプリ →「ダウンロード」でZIPをタップして解凍。
2. Safariで https://github.com にサインイン。GitHubアカウントがなければ作成。
3. 画面メニューから「New repository」を選び、名前を `mochimono-check`、可視性を **Public** にして作成（Initialize READMEにチェックを付けてもよい）。
4. 作ったリポジトリの **Add file → Upload files → choose your files** を選び、iPhoneの「ファイル」アプリの解凍済みフォルダから11ファイルを選択。ファイルはフォルダを作らずリポジトリのトップ階層に置く。
5. **Commit changes**（またはPropose changes）をタップして保存。もしPR作成画面になったらmainへ取り込む。
6. **Settings → Pages** で **Deploy from a branch / main / /(root)** にして **Save**。Settings等が表示されない場合、Safariの「ぁあ」メニューから「デスクトップ用Webサイトを表示」を選ぶ。
7. Pagesの「Visit site」リンクか `https://ユーザー名.github.io/mochimono-check/` をSafariで開く。公開まで数分かかることがある。
8. 「オフライン準備OK」になったらSafariの共有ボタン →「ホーム画面に追加」。ホーム画面から起動した際にも、オンラインで一度「オフライン準備OK」を確認。
9. Wi-Fi・モバイルデータをオフにして、起動・手動チェック・QRスキャンを確認。

**注意** GitHub Pagesは公開サイト。アプリのHTML/JavaScript/アイコンは誰でも閲覧できる。持ち物の個別登録情報はアプリ内で登録して端末ローカルに保存し、GitHubには置かない。

## v1.1 の修正（QR生成エラーへの対策）
- QR生成処理を app.js に内蔵。別ファイル qr-encode.js の取得に失敗しても生成を継続できるように変更。
- QR生成／印刷に失敗した場合は原因の文言を表示。
- Service Workerのキャッシュ名を v1.1 に変更し、更新後のファイルを取得する構成へ変更。
- 既存の持ち物データは変更・削除しない。
- 更新時は app.js と sw.js の2ファイルを既存GitHubリポジトリのトップ階層へ上書きアップロード。
- アプリをオンラインで開き直し、画面左上の小さい文字が「もちもの管理 v1.1」になっていれば新しいコードが読み込まれている。
- キャッシュ更新のため、GitHub Pagesへアップロード直後は一度終了してから再起動（必要に応じて複数回）。ホーム画面版のアプリを削除すると保存データを失うおそれがあるため削除しない。


## v1.2 の変更：QR修正＋確認カレンダー＋クリアゲージ
- **QR生成エラー修正**：QR生成処理を`app.js`に内蔵。`qr-encode.js`の個別読み込みに失敗しても利用可。エラー詳細を表示。
- **円形ゲージ**：今日のチェック率（0～100%）と確認済み個数を大きく表示。スキャン中もクリア数とバーを表示。
- **確認カレンダー**：各日付をタップして「確認できた」「未確認」を項目名で表示。未確認は紛失・忘れ物が確定した意味ではありません。
- カレンダー記録は **v1.2を初めて利用した日から** 作られます。旧v1.0データから過去の日々の未確認品は復元できません。
- 記録は端末内に最大730日分保持。すでに記録された過去日付の持ち物は後日削除・改名しても保持します。
- バックアップ形式は **v2** になり履歴も含みます。旧v1バックアップを読み込むことも可能ですが、履歴は含まれません。
- **既存データの維持**：旧版と同じ`mochimono-check-v1`のlocalStorageを引き続き読み込みます。ホーム画面アプリを消してから入れ直さないでください。

### すでにGitHub Pagesに設置済みの場合：iPhoneで更新
1. `v1_2_update_4files.zip`を保存して「ファイル」アプリで解凍。
2. GitHubの既存リポジトリで、`index.html`、`app.js`、`style.css`、`sw.js` をそれぞれ開いて鉛筆アイコンから更新するか、アップロード操作で既存の同名ファイルを上書きしてコミットします。
3. 4ファイルとも **リポジトリ直下** に置きます。`qr-encode.js`は残して構いません（新バージョンでは読み込みません）。
4. GitHub Pagesの反映後、**Safariでオンラインの公開URLを開き**、「もちもの管理 v1.2」と「きろく」タブを確認。
5. ホーム画面のアプリをいったん閉じて、Wi-Fiをオンにした状態で再起動します。旧キャッシュが残る場合はもう一度閉じて再起動。**アプリ削除は保存データを消す可能性があるため避けてください。**
6. QRボタンで画像生成 → スキャン → クリア数 → カレンダーを確認。

注意：同じURLのブラウザ表示でもQR生成が失敗するなら、iOSのカメラ固有ではなく、WebアプリのJavaScript生成側か読み込み側の問題が疑われます。


## v1.3「もちものフレンズ」— おへやの育成要素
- **みんなのおへや**：登録済みの持ち物を、形をモチーフにした細線のSVGキャラクターとして表示します。筆箱・水筒・ノート・上履き・袋・ハンカチなどは個別デザイン、その他は箱モチーフです。外部画像やゲームエンジンは不要です。
- **うろうろ**：CSSの微小な移動アニメーションです。`prefers-reduced-motion` に従い、動きを抑える設定にも対応します。
- **元気度**：直近最大7登校日（原則平日）の確認状況から算出。未記録日の無制限な遡及減点を避けるため、アプリの使用開始日以前は集計しません。新規利用時は中立から始まり、1回の成功・失敗で極端に落ちません。計算式 `50 + 50×(2×確認日数−対象日数)/(対象日数+2)` を8〜95に制限。スキャンや手動確認は同じ成功として扱います。
- **見た目**：確認が少ないと隅で小さく後ろ向き、増えると段階的に横向き→正面で微笑み、部屋の手前へ移動します。数値変化は連続で、表情の向きは3段階です。
- **当日の減点を回避**：今日まだスキャンしていないことによるペナルティは、その日のうちは発生しません。翌日以降の未確認日は記録がなくても平日なら集計対象になります。
- **おやすみ**：土日を自動的に除外。その他の休校日・旅行日は「きろく」→日付を選択→「この日をおやすみにする」で元気度集計から除外できます。過去日も変更できます。
- **QR照合・ゲージ・履歴・印刷・バックアップ**：v1.2の機能と持ち物の識別子は引き継ぎます。データの初期化やQRシールの再発行は不要です。履歴バックアップ内におやすみフラグが含まれます。
- **軽さ**：24個までのキャラクターをおへやに描画。それ以上はおへやでは省略されますが、持ち物リスト・QR照合・履歴管理は全件対応です（最大200件）。

### iPhoneでv1.3に更新するとき
1. **先にアプリの「もちもの」→「バックアップを書き出す」でデータを保存**するのがおすすめです。
2. `MochimonoCheck_v1_3_update_4files.zip`を解凍し、`index.html`、`app.js`、`style.css`、`sw.js` をGitHubリポジトリ直下に**既存ファイルと同名で上書き**します。余分なサブフォルダを作らず、他のファイルは変更しません。
3. GitHub Pages反映後に**Safariで公開URL**をオンラインで開き、上部の小さい文字が「もちものフレンズ v1.3」と表示されることを確認します。旧ページが表示される場合はページを再読み込みしてください。
4. **ホーム画面のアプリは削除せず**、オンラインで開き直します。Service Workerのキャッシュが新しくなるまで、再起動・再読み込みを数回繰り返す場合があります。
5. 登録済み持ち物が表示されることを確認してからQR生成を試してください。iPhone 8実機での動作は未検証のため、カメラが起動するかも確かめてください。

### データ取り扱い
ゲームの変化は日々の履歴から再計算するので、育成用データベースや通信は不要。端末内の持ち物・履歴保存領域を従来通り使用します。端末の日付を変更した場合は表示が不正確になる場合があります。
